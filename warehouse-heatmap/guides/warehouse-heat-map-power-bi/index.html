How to build a warehouse heat map in Power BI

A practical walkthrough: get coordinates for every bin location, model them next to your inventory and pick data, write the DAX measures, and choose a visual that shows the warehouse the way your team walks it.

Unclocked Studios · October 15, 2026 · 8 minute read

A table can tell you that location 14-03-C has 212 days of stock. It can't tell you that the twenty oldest pallets in the building sit in the same two aisles, right next to your fastest movers. That's the job of a warehouse heat map: draw every storage location where it physically is, then color it by a number you care about.

Power BI is a good place to build one, because the numbers are usually there already. Inventory snapshots, pick lines, and replenishment tasks come out of the WMS and into a semantic model every night. What's usually missing is the layout. This article covers how to add it, and what to do once the warehouse is on screen.

What a warehouse heat map needs

Every warehouse heat map, whatever tool draws it, comes down to two tables.

The first is a location table: one row per bin, slot, or pallet position. It holds the location ID and where that location is on the floor. The second is your activity or inventory data, keyed by the same location ID. The heat map joins them and colors each location by a measure.

A location table for three bins in one aisle, in inches
Location IDAisleLevelXYZWidthLengthHeight
A01-01-AA01A000404848
A01-01-BA01B0048404848
A01-02-AA01A4000404848

X and Y place the bin on the floor. Z is the height of its base, which is what turns a flat floor plan into rack levels. Width, length, and height are optional, but they make a mixed warehouse read correctly: a floor-stack lane and a carton-flow slot aren't the same size, and they shouldn't look it.

Pick one unit, inches, feet, or centimeters, and use it for every column. Mixed units are the most common reason a layout comes out stretched or overlapping.

Where bin location coordinates come from

Most WMS exports don't include coordinates. There are three practical ways to get them.

From the WMS or a slotting tool

Check first. Some systems store travel-sequence or slotting coordinates for each location, and a report writer can usually add them to an existing location export. If they exist, you're done with this step.

From an AutoCAD drawing

If the facility drawing has racks drawn as blocks, AutoCAD's DATAEXTRACTION command can export each block's name, attributes, and insertion point (Position X and Position Y) to a CSV. That gives you coordinates in drawing units. Two things to check before loading them:

  • Insertion points aren't always the corner of the bin. If the block's base point is its center, subtract half the width and length.
  • Drawings often show one block per rack bay, not per level. You'll need to expand each bay into its levels, with a Z for each.

If your drawing doesn't have clean blocks, or you'd rather not spend a week on it, this is exactly what our warehouse mapping service does: we turn the drawing into a coordinate CSV and confirm units, labels, and level heights with you first.

From a regular grid

Many racked areas are regular enough to calculate. If aisles are 120 inches apart, bays are 48 inches wide, and levels are 60 inches apart, every location's position follows from its name. In Power Query, after splitting the location ID into aisle, bay, and level numbers, add three custom columns:

X = ([Aisle Number] - 1) * 120
Y = ([Bay Number] - 1) * 48
Z = ([Level Number] - 1) * 60

Real buildings have columns, cross aisles, and the odd short rack, so check the result against the floor plan. Fix the exceptions by hand rather than complicating the formula.

Model the layout in Power BI

Load the location table as its own dimension, separate from inventory. Relate Layout[Location ID] to each fact table, one to many, filtering in a single direction. Use the layout table for every field that describes the location: coordinates, sizes, aisle, level, zone, and location type.

The reason is empty bins. If the locations come from the inventory table instead, an empty bin has no inventory row, so it never appears, and the empty locations are often the ones you're looking for. With the layout in its own table, every location is drawn whether or not it has stock today. In the visual, you may also need to turn on Show items with no data for the location field, because Power BI leaves out rows where every measure is blank.

Give every location a unique ID. If you run more than one building in the same model, include the site in the ID or the key, because A01-01-A probably exists in all of them.

Write the measures to color by

Color the map with measures, not columns, so it responds to slicers for date, client, or zone. A few that warehouse teams use most:

On Hand Units = SUM ( Inventory[Quantity] )

Picks Last 28 Days =
CALCULATE (
    COUNTROWS ( PickLines ),
    DATESINPERIOD ( 'Date'[Date], MAX ( 'Date'[Date] ), -28, DAY )
)

Location Fill % =
DIVIDE ( [On Hand Units], SUM ( Layout[Capacity Units] ) )

Days Since Last Pick =
VAR LastPick = CALCULATE ( MAX ( PickLines[Pick Date] ) )
RETURN
    IF ( ISBLANK ( LastPick ), BLANK (), DATEDIFF ( LastPick, TODAY (), DAY ) )

Each one answers a different question, so it's worth having several and letting report users switch between them. A field parameter, or a small disconnected table with a SWITCH measure, lets one heat map show quantity, picks, or fill without building three pages.

Choose a visual for the map

Power BI doesn't have a warehouse map built in, but there are a few ways to draw one.

  • The scatter chart. Put X on the x-axis, Y on the y-axis, and color the points with conditional formatting. It's built in and quick to try. Every location becomes a dot of the same size, levels stack on top of each other, and large layouts are sampled, so it works best for a single floor-level area.
  • Image or shape map visuals. Several custom visuals color the shapes in an SVG floor plan by a measure. They look accurate, but someone has to draw and name every shape, and the drawing has to be redone when the layout changes.
  • A 3D warehouse visual. Unclocked 3D Heatmap, our own visual, reads the location table directly and draws each bin at its X, Y, and Z with its real size, so rack levels stay separate. You can orbit the warehouse in 3D or switch to a flat 2D plan, search for a location, and filter by aisle or level inside the visual.

The right choice depends on the building. A single-level pick area of a few hundred locations is fine as a scatter chart. Racked storage with several levels, where the question is often "which level," is where 3D earns its place.

Make the colors mean something

A heat map is only as useful as its color scale. Three choices make the biggest difference.

Gradient or bands. A smooth gradient shows small differences and suits exploration. Color bands, with hard breaks at set values, suit operational rules: a location over 90% full is a problem, and 89% isn't. If your team already has thresholds, use bands that match them.

A fixed range when you compare. An automatic range rescales to whatever is on screen, so red in a quiet week and red in peak season mean different things. When you compare weeks, sites, or zones, set a manual minimum and maximum.

Handle the outliers and the zeros. One location with 4,000 picks will push everything else into the same pale color. Capping outliers keeps the rest of the warehouse readable. And decide whether zero means "empty" or "a real zero." For fill, an empty location is information; for picks, a zero might be the location you should re-slot.

If targets change with the selection, for example a different aging threshold per client, the thresholds themselves can come from DAX measures instead of fixed numbers.

Questions worth putting on the map

  • Where is aging stock concentrated? Color by days on hand or days since last pick. Old stock clustered near the dock is space you're paying for twice.
  • Are fast movers slotted well? Color by picks over the last four weeks. Hot locations on top levels, or at the far end of the building, are slotting candidates.
  • Where is replenishment pressure building? Color by open replenishment units or locations below their minimum.
  • How full is the building, really? Color by fill percentage. A warehouse at 85% overall can still be full in the zones that matter.
  • Which locations need a closer look? Rank exceptions, such as negative stock or locations with stock but no pick in 180 days, and work through them on the map.

Common mistakes

  • Mixed units. Coordinates in feet and sizes in inches produce a layout that looks almost right, which is worse than one that's obviously wrong.
  • Building the layout from inventory. Empty locations disappear, and so do the gaps you wanted to see.
  • Duplicate location IDs across buildings or after a re-labeling project.
  • Forgetting levels. Without Z, every level of a rack lands in the same spot, so one bin hides the others.
  • Showing everything at once. A 20,000-location building on one screen is hard to read. Filter to the zone or level the question is about.
